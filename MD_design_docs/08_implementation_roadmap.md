Phase 1: Data Acquisition & Preprocessing (The Foundation). You cannot split or train without a unified, deduplicated dataset. This phase executes 06_task5_data_pipeline_plan.md.  Execute the Pulls: Script the paginated DBAASP REST API pull. Simultaneously, download the bulk files from DRAMP, Hemolytik2, HemoPI2, and the QMAP benchmark package.  Run SMILES Conversion: Pass the sequences through your conversion stack, using p2smi for cyclic peptides and non-canonical residues, and standard RDKit for the linear backbones.  Validate and Deduplicate: Run round-trip and mass-sanity checks on the generated SMILES. Generate a stable peptide_uid hash based on sequence and modification signatures to merge duplicates across sources.  Normalize Labels: Convert all HC50 and MIC values to µM (using RDKit-computed molecular weights for modified peptides) and apply the log-transformation.  

Phase 2: Embedding, Clustering, & Splitting (The Yardstick)With a clean dataset, you must establish the homology-aware evaluation yardstick before touching any training code. This executes 07_task5_splitting_strategy_plan.md.  Generate Base Embeddings: Pass your deduplicated peptide list through the base pretrained PeptideCLM-2 encoder to extract mean-pooled final-layer embeddings.  Perform Joint Clustering: Run k-means clustering (sweeping for k=4–6 based on silhouette/DB/CH scores) on the union of all HC50 and MIC peptides. Do not split the tasks independently, or you will cause data leakage across the shared encoder later.  Run the Homology Cross-Check: Execute a sequence-identity graph partition (via graph-part or the QMAP masking utility) as an independent check against your embedding clusters.  Leakage Validation: Measure the maximum sequence identity between your train and test folds to ensure it aligns with QMAP's ~50-60% safety baseline.  

Phase 3: The Model Selection Pilot (The Decider)Do not assume hybrid-small is the winner. This phase executes 05_task5_model_selection_plan.md.  Establish the Baseline: Run the physicochemical-descriptor regressor on your new splits. Every deep learning model must clear this bar.  Run the Pilot Grid: On a subset of your split data, run a short pilot evaluating hybrid-small, mtr-small, mlm-small, and mlm-large.  Evaluate Two Ways: For each candidate, run both a cheap frozen-encoder probe and a short (10-epoch) full fine-tune.  Lock the Architecture: Pick the winning base model based on absolute performance relative to compute cost.  

Phase 4: Core Multitask Implementation (P2 & P3)Now you build the actual training loops and heads around your chosen model. This executes 04_task5_multitask_architecture_plan.md.  Build the Shared Architecture: Implement the mask-aware mean pooling function, the shared Linear+SiLU projection layer, and the individual 2-layer MLP task heads.  Implement P2 (Single-Task HC50): Train the HC50 head using the two-stage protocol: freeze the encoder and train the head to convergence, then unfreeze the top N blocks with a lower learning rate.  Implement P3 (Multitask Addition): Add the MIC head to the module. Re-freeze the encoder, initialize the MIC head (run the ablation comparing a copied HC50 initialization vs. a fresh Xavier initialization), and train using the masked multitask loss and stratified batch sampler.  

Phase 5: Ablations & Final ValidationWith the core system working, you can test the secondary hypotheses.The Warm-Start Ablation: Execute 03_task5_warmstart_encoder_ablation_plan.md by fully reproducing the PAMPA-fine-tuned checkpoint from the authors' script (since they did not publish the weights). Run this checkpoint through the exact P2 protocol to see if permeability features actually transfer to your lysis targets.  Therapeutic Index (TI) Ablation: Compare the default derived TI (log(HC50) - log(MIC)) against a third, learned TI head trained only on the subset of peptides that possess both labels.
